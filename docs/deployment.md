# Linux 部署

## 环境准备

在目标 Linux 系统准备 Python、虚拟环境工具以及串口和 I2C 驱动。Python 版本与 CPU 架构需能安装统一依赖清单中的包。语法兼容不等于已验证所有系统镜像或架构的运行能力。

运行时直接使用 SCS 舵机总线和 QMI8658，不包含厂商特定 GPIO 库。硬件和电气要求见 `hardware.md`。

## 安装

在源码根目录执行：

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

统一依赖清单包含：

- 服务与硬件：FastAPI、Uvicorn、pyserial、smbus2。
- 数值与推理：NumPy、ONNX Runtime。
- 测试与维护：ONNX、HTTPX、Black。

依赖版本和 Python 条件以 `requirements.txt` 为准。若目标平台缺少匹配的安装包，应先验证依赖兼容性，不以忽略安装错误或随意替换版本作为部署完成的依据。

部署目录需包含 Python 源码、`models/` 和 `assets/web/`。资源路径相对源码仓库解析，而非相对终端的当前目录。

## 设备权限

检查所用串口与 I2C 设备节点：

```bash
ls -l /dev/ttyUSB* /dev/ttyACM* /dev/i2c-*
```

某些类型没有匹配节点时，`ls` 会提示路径不存在。板载串口可能使用其他名称，应按平台配置确认。

运行用户需要所选设备的读写权限。使用发行版提供的设备用户组或受限的 udev 规则，不建议通过开放所有用户写权限解决访问问题。还应确认设备未被其他控制进程占用。

## 启动

```bash
python -m zhiban_runtime \
  --servo-device /dev/ttyUSB0 \
  --servo-baud 1000000 \
  --i2c-bus 1 \
  --host 127.0.0.1 \
  --port 9527
```

参数中的设备路径和总线编号为示例，须替换为实际配置。默认探测 QMI8658 地址 `0x6a` 与 `0x6b`；需要固定地址时使用 `--imu-address`。

上例仅监听本机。需要从可信局域网访问时可选择相应监听地址，但服务本身没有认证或 TLS，不应直接公开到互联网。

初始模式为 `shadow`。检查反馈和机械状态后，再通过工作台显式进入控制模式。

## 运行检查

- 工作台应显示完整舵机反馈和有效 IMU 状态。
- 检查 `last_error`、反馈时延、实测频率和漏周期计数。
- 预热至少 5 秒后运行 `python tools/check_control_rate.py --duration 60`。
- 用途不同的系统服务或负载可能影响调度，应在实际部署负载下验收。

## 停止与维护

停止服务前先卸力，确认机器人处于安全状态。服务关闭流程会请求卸力并释放设备，但不应以软件关闭替代物理断电手段。

进入标零、中位设置或修改 ID 前确认机器人固定方式及目标设备。维护操作可能包含持久化参数写入，不能当作普通运行状态检查。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 串口无法打开 | 路径、访问权限、驱动及其他进程占用 |
| 无法读取 IMU | I2C 驱动、总线编号、地址、接线和电平 |
| 部分舵机无反馈 | ID、供电、总线接线、波特率与适配器 |
| 模型无法加载 | 模型目录、文件完整性及依赖兼容性 |
| 无法从其他设备访问 | HTTP 监听地址、网络路径和防火墙 |
| 实测频率不足 | 按 `realtime.md` 检查 I/O、回调和调度耗时 |
